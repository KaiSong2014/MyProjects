# 综合报价系统

综合报价系统是一套面向软件项目报价的 Codex Skill。它从需求文档、会议记录或已有报价中筛选本期范围，拆分功能模块与实际参与工种，结合已确认的费率、采购价和税率，生成统一格式的单工作表 Excel 报价清单。

技能以资深项目经理、产品经理和软件架构师的视角工作，覆盖互联网软件、工业软件、科研软件、SaaS、PaaS，以及项目配套的基础硬件采购。

## 能解决什么问题

- 从多份需求和修订记录中区分本期、二期、可选、已有能力和待确认项，避免扩大报价范围。
- 把需求拆成可验收功能，再按实际交付工种估算，避免每个功能机械复制一整套团队。
- 识别共用登录、权限、接口、部署及已有算法，按增量工作计价，减少重复收费和无依据的高配置报价。
- 固定列名、字体、对齐和颜色，减少交付客户前的格式调整。
- 将人工、硬件、第三方服务及不同税组放在同一清单内，保留金额公式。
- 参数缺失时显示“待确认”，避免把未知金额当成零或输出虚假的低总价。

## 报价清单格式

最终 Excel 仅包含一张可见工作表，名称为 `报价清单`，不包含隐藏页、汇报页、分析页或数据页。九列名称及顺序固定如下：

| 序号 | 列名 | 内容及对齐 |
| --- | --- | --- |
| 1 | 序号 | 连续编号，向左对齐 |
| 2 | 功能模块名称 | 业务模块，水平及垂直居中；同模块连续行纵向合并 |
| 3 | 功能模块描述 | 当前工种承担的功能及交付边界，向左对齐 |
| 4 | 工种 | 实际参与的工种，水平及垂直居中 |
| 5 | 人工单价 | 人民币元/小时，水平及垂直居中 |
| 6 | 工时 | 人时，水平及垂直居中 |
| 7 | 模块总价 | 当前明细金额，水平及垂直居中 |
| 8 | 模块合计 | 同模块明细之和，向左对齐；对应模块名称合并 |
| 9 | 备注建议 | 范围、复用条件、采购依据及待确认事项，向左对齐 |

全部内容使用宋体 12 磅（小四），垂直居中，并按内容换行、设置行高。正文保持无填充、黑字，不加粗、不倾斜、不加下划线。表头允许深灰 `#404040` 填充、白字和加粗；末尾 `税前总价`、`税后总价` 的金额单元格用相同深灰高亮，仍不加粗。其他单元格不填背景色。

硬件和第三方服务独立列为非人工行，人工单价、工时留空。数量、单位、未税采购单价、来源和日期写入 `备注建议`；安装与联调另列人工费用。

## 计价方式

```text
人工行模块总价 = ROUND(人工单价 × 工时, 2)
采购行模块总价 = ROUND(数量 × 未税采购单价, 2)
模块合计 = 同模块明细的模块总价之和
税前总价 = 全部明细的模块总价之和
每个税组税额 = ROUND(该税组未税合计 × 已确认税率, 2)
税后总价 = 税前总价 + 各税组税额
```

税前总价不重复加入模块合计。人工单价或工时缺失时，该行金额、所属模块合计及项目总价显示 `待确认`。仅税率缺失时，税前金额可正常计算，税后金额显示 `待确认`。确认的零值与缺失值分别处理。

费率优先采用用户参数或同口径历史项目；税率采用用户确认的计价口径。技能不内置通用低价费率、法定税率或默认利润比例。预算不足时建议明确的范围缩减、复用或分期方案。

## 安装与调用

将整个 `comprehensive-quotation` 文件夹放到项目的 `.agents/skills/` 中，或个人的 `~/.agents/skills/` 中。保留 `SKILL.md`、`agents`、`references` 和 `scripts` 的相对目录关系。[Codex 本地技能目录与发现方式](https://learn.chatgpt.com/docs/build-skills)。

也可以在 Codex 中请求 `$skill-installer` 从这个 GitHub 仓库的技能目录安装。

提交一份需求文档，然后输入：

```text
使用 $comprehensive-quotation 分析附件，筛选一期范围并拆分软件功能及必要硬件。
使用附件明确提供的人工费率和税率，按固定九列生成单工作表 Excel 报价清单。
没有依据的参数标为待确认，不把二期、可选项或已有能力重复计入价格。
```

为便于形成完整报价，建议同时提供各工种小时费率、预算含税口径、税率、已有系统及接口情况、采购数量和价格依据。提供人天费率时，需要说明每天按多少小时换算。

## 工作流程

1. 读取需求、附录和修订记录，记录来源并处理版本与冲突。
2. 确定本期范围、复用条件、架构和验收边界。
3. 按业务模块及实际工种估算人时，核对采购和第三方费用。
4. 将分析后的结果整理为 JSON，生成带公式的 Excel。
5. 重算并独立核对金额，检查固定格式，渲染整个清单确认文字完整显示。

真实硬件选型及报价需要查询当时的厂商或授权供应商资料，并记录来源、查询日期、含税口径、兼容条件、交期和保修。无法查询时保留待询价，不把测试型号或示例价格当成真实行情。

## 直接运行生成器

技能说明可由具备文件读取和表格能力的代理使用。附带的 JavaScript 生成器另外依赖 Node.js 和 `@oai/artifact-tool`，需要在提供该依赖的工件运行环境中执行；本仓库不包含该依赖或本机运行时文件。普通 Node.js 环境未提供该包时，不能直接运行生成器。

Python 校验器仅使用标准库。输入格式见 [input-schema.md](references/input-schema.md)，估算规则见 [estimation.md](references/estimation.md)。

从技能目录执行：

```bash
node scripts/build_quote.mjs examples/quote.json outputs/quotation.xlsx --preview-dir outputs/previews
python3 scripts/validate_quote.py outputs/quotation.xlsx
```

人工单价、工时和税率可在 Excel 中修改，相关金额公式随之更新。采购金额公式使用核对后的数量与单价；调整采购参数时也应同步修改备注中的数量和价格依据。

## 测试材料

| 材料 | 主要检查内容 |
| --- | --- |
| 互联网 SaaS | 租户隔离、客户及合同回款流程、已有身份服务复用、导入验证 |
| 工业软件与硬件 | 两种设备协议、断网补传、告警、现场实施、非人工采购及混合税率 |
| 科研软件 | 已有算法集成、任务并发、复现、曲线和报告，不重复计算法研发 |
| PaaS | 现有容器平台复用、配额审批、发布回滚、监控与身份集成 |
| 冲突和缺失信息 | 版本冲突、人天换算、费率与税率缺失，不让引用的旧格式覆盖规则 |

每次只提交对应案例，按 [测试说明](tests/test-guide.txt) 检查结果。案例中的费率、税率、设备型号和价格是虚构测试参数。示例报价只演示格式及公式，不是对工业案例全部范围的正式报价。

生成器已验证混合税率、单价调整、零税率、零工时、缺失费率、缺失工时、设备待询价、重复模块归并及负数输入拒绝。示例 Excel 已完成格式和金额检查，并通过 LibreOffice 重算核对；五份 Word 测试材料已逐页渲染检查。这些检查覆盖生成与格式逻辑，不代表所有需求的模型拆分质量已有固定标准答案。
